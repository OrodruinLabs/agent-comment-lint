# Releases 1.5.0 to 1.7.0: More Languages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let Ruby, TOML, Dockerfile, Makefile, Go, Java, Rust, Kotlin, Swift and C/C++ shops use agent-comment-lint.
Each language is lexed honestly enough that strings never read as comments and anything unterminated is exit 2.

**Architecture:**
- **Hash-comment languages** get small families built on the line-at-a-time scanner
  (`lexers/linescan.py`, `lexers/hashlike.py`).
- **C-family languages** share one new configurable character lexer, `lexers/clike.py`, modeled on
  `lexers/javascript.py`. It emits whole `/* */` comments through `LineBuilder.emit_block_comment`. Each language is a
  `Syntax` value plus a `Family`.
- **Files with no extension** (`Dockerfile`, `Makefile`) are matched by name through a new `Family.names` field.

**Tech Stack:** Python 3.9+ standard library and `unittest`.

**Spec:** `docs/superpowers/specs/2026-10-29-next-level-roadmap-design.md`, section 7.

**Depends on:** releases 1.2.0 and 1.3.0 merged. 1.4.0 isn't required. If 1.4.0 shipped as several releases, shift
these version numbers up.

**Releases (designer's call on grouping):**

| Release | Tasks | Languages |
| --- | --- | --- |
| 1.5.0 | 1 to 5, 12 | Ruby, TOML, Dockerfile, Makefile |
| 1.6.0 | 6 to 8, 12 | Go, Java, Rust |
| 1.7.0 | 9 to 11, 12 | Kotlin, Swift, C/C++ |

## Global Constraints

- Python 3.9 or newer, standard library only at run time (E1).
- Exit codes: 0 clean, 1 violations, 2 could not scan. Exit 2 is never downgraded (E2). A string, raw string, text
  block, heredoc or block comment that never closes raises `LexError` with its opening line.
- No configurable limits, no inline suppression (E4). `--all` stays clean (E5). Code lines are at most 120
  characters (E6). Test first (E7).
- One version per release, in both places (E8). Each release moves findings for the languages it adds, so it is a
  minor release, and its changelog entry names each language.
- The rules (`rules.py`) don't change. A new language gets C1, C3, C5 and C7 exactly as the existing ones do. Any
  doc-comment exemption is decided by the owner in Task 6 Step 0, and lives in the lexer's output, not in the rules.
- Every new extension or name is matched by both `files:` lines in `.pre-commit-hooks.yaml`. Task 1's test enforces
  that.
- A shape a lexer reads wrongly on purpose is pinned in `tests/test_known_false_positives.py` and listed in
  `docs/reference.md` "Known false positives".
- Everything works on macOS, Linux and Windows. Lexers are pure Python, and CI from 1.2.0 covers all three.
- Lexer tests use `support.comments(path, text)` and `support.found(path, text)`, as `tests/test_javascript.py`
  does.

## Review Focus

1. **Names that merely contain a covered name**, such as `Makefile.bak`, `MyDockerfile` or `Dockerfile.orig`, should
   not be judged. Test in Task 1.
2. **Windows line endings** (`\r\n`) in a C-family file should lex the same as `\n`. Test in Task 6.
3. **A string still open at end of file** should be exit 2 in every new language. Each language task has one
   test.
4. **A `#` inside a string** in Ruby, TOML and Makefile recipes should not open a comment. Tests in Tasks 2, 3 and
   5.
5. **Rust lifetimes** (`'a`) should not open a character literal and swallow the rest of the line. Test in Task 8.

### Task 2: Ruby

**Files:**
- Create: `agent_comment_lint/lexers/ruby.py`
- Modify: `agent_comment_lint/lexers/__init__.py` (`FAMILIES`), `.pre-commit-hooks.yaml` (`files:`)
- Test: `tests/test_ruby.py`, `tests/test_known_false_positives.py`

**Interfaces:**
- Produces: `ruby.FAMILY = Family("ruby", (".rb", ".rake", ".gemspec"), HASH_ONLY, lex, ("Gemfile", "Rakefile"))`,
  with `HASH_ONLY` from `hashlike`.
- Behaviour:
  - Lines are scanned with `linescan.scan_lines`.
  - Heredoc payload lines are content. The opener is `<<`, `<<-` or `<<~` directly followed by an identifier,
    optionally quoted, and preceded by start of line, whitespace, `(`, `,` or `=`, never by a word character or `)`.
  - `=begin` to `=end` lines, each starting at column 0, are one comment block. Every line between them is a comment
    line with its text as prose.
  - An unterminated heredoc or `=begin` raises `LexError`.

- [ ] **Step 1: Write the failing tests in `tests/test_ruby.py`**

```python
def test_a_two_line_comment_is_one_block(self):
    self.assertEqual(found("a.rb", "# one\n# two\nx = 1\n"), [("C1", 1)])

def test_interpolation_and_hashes_in_strings_are_not_comments(self):
    self.assertEqual(comments("a.rb", 'puts "#{name} # ADR-9"\n'), [[]])

def test_heredoc_payload_is_content(self):
    self.assertEqual(found("a.rb", "s = <<~EOS\n  # ADR-9\nEOS\n"), [])

def test_an_append_is_not_a_heredoc(self):
    self.assertEqual(found("a.rb", "items << EOS\n# see ADR-9\n"), [("C3", 2)])

def test_a_begin_end_block_is_one_block(self):
    self.assertEqual(found("a.rb", "=begin\none\ntwo\n=end\nx = 1\n"), [("C1", 2)])

def test_files_named_gemfile_and_rakefile_are_covered(self):
    self.assertEqual(found("Gemfile", "# one\n# two\n"), [("C1", 1)])

def test_an_unterminated_heredoc_cannot_be_lexed(self):
    with self.assertRaises(LexError):
        engine.check_text("a.rb", "s = <<~EOS\nnever closed\n")
```

The lexer places the `=begin` block with `BlockLine` entries, as `LineBuilder.emit_block_comment` does: `=begin`
opens it with no prose, each line between is prose, and `=end` closes it. Since 1.1.0, C1 reports the span of the
prose lines only, so the finding is on line 2.

Pin these in `tests/test_known_false_positives.py`:
- `x = ?#` reads a comment;
- `%w[a #b]` reads a comment;
- `/#/ =~ s` reads a comment.

Each gets one comment line saying the line scanner doesn't know Ruby's character, percent and regex literals.

### Task 6: The C-family lexer, and Go

**Files:**
- Create: `agent_comment_lint/lexers/clike.py`
- Modify: `agent_comment_lint/lexers/__init__.py`, `.pre-commit-hooks.yaml`
- Test: `tests/test_clike.py`, `tests/test_go.py`

- [ ] **Step 0: Owner decision on doc comments (stop and ask)**

Ask the owner this question:

> **How should C1 treat multi-line doc comments in Go, Java, Rust, Kotlin, Swift and C/C++?**
> - **(A) As every language today:** one prose line per block. Complete one-line `@tag` lines don't count, as with
>   JSDoc. That means Rust's `# Examples` sections and multi-paragraph Javadoc are blocked.
> - **(B) As (A), but lines inside a fenced code example in a doc comment are not prose** (` ``` ` in Rust, Kotlin
>   and Swift; `<pre>` in Java).
>
> I recommend (A). It matches the policy everywhere else, and agents are the ones who write long doc blocks.

Record the answer in the spec's section 9. If the answer is (B), `Syntax.doc_code_fences` (below) is set for the
languages that have fences, and every language task adds the (B) test listed in it.

**Interfaces:**
- Produces: `clike.Syntax = namedtuple("Syntax", ["nested_blocks", "multiline_strings", "raw_string", "text_block",
  "char_literal", "line_continuation", "doc_code_fences"])`.
  - `nested_blocks`: a bool.
  - `multiline_strings`: a bool. A plain `"..."` string may cross lines (Rust).
  - `raw_string`: one of `None`, `"backtick"` (Go), `"rust"` (`r#"…"#`, `br"…"`), `"swift"` (`#"…"#`) or `"cpp"`
    (`R"delim(…)delim"`).
  - `text_block`: a bool. Triple-quoted `"""…"""` may cross lines (Java, Kotlin, Swift).
  - `char_literal`: one of `"simple"` or `"rust"`. `"rust"` makes a `'` start a character literal only when it closes
    as one, so `'a` with no close is a lifetime.
  - `line_continuation`: a bool. A `//` comment ending in `\` continues onto the next line (C/C++).
  - `doc_code_fences`: a bool, from Step 0.
- Produces:
  - `clike.lexer(syntax) -> callable`, returning a `lex(text) -> [Line]` built on `LineBuilder`. It reads text that
    `base.normalized` has normalised, so `\r\n` behaves as `\n`, and places multi-line `/* */` comments with
    `emit_block_comment`.
  - `clike.MARKERS = Markers(hash=False, slash=True, block=True, star=False)`.
- Produces: `go.FAMILY = Family("go", (".go",), clike.MARKERS, clike.lexer(GO))`, where
  `GO = Syntax(False, False, "backtick", False, "simple", False, False)`. It lives in a new
  `agent_comment_lint/lexers/go.py`.
