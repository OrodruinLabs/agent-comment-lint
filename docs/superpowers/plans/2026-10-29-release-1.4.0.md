# Release 1.4.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Block a comment-policy violation before it lands in Copilot, Windsurf/Devin, Kiro, Cursor, Codex and Gemini
(or Antigravity), on macOS, Linux and Windows. Be honest about where a crash or timeout lets the write through.

**Architecture:**
- `--hook` gains `--agent NAME` (default `claude`).
- `hook.py` gets an adapter per agent. Each one turns that agent's event into a list of the `Target`s the existing
  judging path already handles. Two new pseudo-tools cover what Claude's tools don't (Kiro's insert and append), and
  one covers Codex patches.
- Templates under `integrations/<agent>/` call the installed command through a guard script for each operating
  system, which turns a missing command or any failure into exit 2.
- Every adapter's tests are built from a real captured event, stored as a fixture.

**Tech Stack:** Python 3.9+ standard library and `unittest`; POSIX `sh` and Windows `cmd` guard scripts.

**Spec:** `docs/superpowers/specs/2026-10-29-next-level-roadmap-design.md`, section 6, plus the reworded E3 in
section 3.

**Depends on:**
- releases 1.2.0 (PyPI, the hook renderer, operating-system support) and 1.3.0 (hook dispatch on
  `hook_event_name`), both merged;
- the agents' payload shapes, from research dated 2026-10-28. A captured fixture overrides them wherever the two
  disagree.

## Global Constraints

- Python 3.9 or newer, standard library only at run time (E1).
- Exit codes: 0 clean, 1 violations, 2 could not scan. Exit 2 is never downgraded (E2).
- Reworded E3: in hook mode, every rejected write reaches the agent through that agent's documented block signal, and
  every crash or failure to scan is exit 2. A JSON shim on exit 0 is allowed only for an agent whose capture shows it
  reads the reason only that way.
- No configurable limits, no inline suppression (E4). `--all` stays clean (E5). Code lines are at most 120
  characters (E6). Test first (E7). One version, `1.4.0` (E8).
- `--agent claude` (the default) behaves byte for byte as in 1.3.0. The whole existing suite proves it.
- Everything works on macOS, Linux and native Windows. Every template has a POSIX form and a Windows form, and both
  are tested.
- Fail-closed is promised only where the agent offers a setting for it. README states each agent's behaviour per
  operating system.
- Support is not claimed in README for an agent until one live blocked write was seen in it.
- Run one test file with `python3 -m unittest discover -s tests -p 'test_agents.py' -k NAME`.

## Review Focus

1. **A tool that writes no file**, such as Kiro `fs_read` or Gemini `read_file`, should be let through by every
   adapter. Test in Task 1, through the shared adapter test.
2. **A Codex patch that touches several files**, with only the second one violating, should block and name that
   second file. Test in Task 6.
3. **A Codex patch that deletes a file** should not be judged and should not crash. Test in Task 6.
4. **A guard whose command reports violations** (exit 1) should exit 2, not 1. Test in Task 1.
5. **An adapter given an event without a file path** should block as "not the event", not let the write through.
   Test in Task 1, through the shared adapter test.

### Task 1: Adapters, `--agent`, the capture script and the guards

**Files:**
- Modify: `agent_comment_lint/hook.py`
- Modify: `agent_comment_lint/cli.py` (parser, `_run_hook`)
- Create: `integrations/capture/capture-event.sh`, `integrations/capture/capture-event.cmd`
- Create: `integrations/guard/agent-comment-lint-guard.sh`, `integrations/guard/agent-comment-lint-guard.cmd`
- Create: `tests/test_agents.py`, `tests/fixtures/agents/` (directory)
- Test: `tests/test_cli.py` (usage), `tests/test_packaging.py` (guards)

**Interfaces:**
- Produces, in `hook.py`:
  - `Target = namedtuple("Target", ["tool", "path", "tool_input", "must_apply"], defaults=[False])`.
  - `ADAPTERS`, a dict from agent name to `adapter(event: dict) -> list[Target]`. It holds only `"claude"` in this
    task. The Claude adapter returns `[target(event)]`, or `[]` when `target` returns None. `target()` keeps its
    behaviour.
  - `targets(event, agent) -> list[Target]`. It raises `HookInputError` when `event` is not a dict, and otherwise
    returns `ADAPTERS[agent](event)`.
- Produces, in `cli.py`:
  - `--agent NAME`, whose choices are `sorted(hook.ADAPTERS)`, default `claude`. Using it without `--hook` is a usage
    error (exit 2), as `--json` with `--hook` is today.
  - `_run_hook` loops over `hook.targets(...)` and judges each one.
  - The `hook_event_name` dispatch from 1.3.0 runs only for `claude`.
  - When `proposed_text` is None for a target with `must_apply`, the run records
    `(relative, None, PATCH_NOT_APPLIED)` with
    `PATCH_NOT_APPLIED = "the edit does not apply exactly to the file on disk, so it cannot be judged"`.
- Produces, in `tests/test_agents.py`:
  - `fixture(name) -> dict` loads `tests/fixtures/agents/<name>.json`.
  - `AdapterContract`, a mixin each agent's test class uses. It sets `agent`, `write_fixture`, `non_write_fixture` and
    `pathless_fixture`, and gets three tests: the write fixture yields at least one Target; the non-write fixture
    yields `[]` (Review Focus 1); the pathless fixture raises `HookInputError` (Review Focus 5).
- Produces, the guard scripts. Each takes the agent name as its only argument:
  - **Missing command:** if `agent-comment-lint` is not on PATH, print `Blocked: agent-comment-lint is not installed.`
    to stderr and exit 2.
  - **Otherwise:** run `agent-comment-lint --hook --agent <name>` with stdin passed through, exit 0 on 0, and exit 2 on
    anything else.
- Produces, the capture scripts: append standard input, followed by a newline, to the file named by
  `AGENT_COMMENT_LINT_CAPTURE`, then exit 0.

### Tasks 2 to 7: one adapter each

Every adapter task has the same eight steps. Each task below lists only what is specific to it: its fixtures, its
mapping, its template, its block channel and its fail-closed behaviour.

- [ ] **Step 1: Capture (owner, stop and ask).** Ask the owner to install the agent's capture template on macOS or
  Linux, and on Windows if they have it. The template is the agent's config pointing at
  `integrations/capture/capture-event.sh` or `.cmd`. In it, the owner asks the agent to (a) create a file, (b) edit a
  file, and (c) read a file. Save the captured events as `tests/fixtures/agents/<agent>-write.json`, `-edit.json` and
  `-read.json`. Build `-pathless.json` from the write fixture with its path field removed.
- [ ] **Step 2: Write the failing tests.** Add a test class for the agent in `tests/test_agents.py` using
  `AdapterContract`. Add one exact-mapping test per fixture, asserting the `Target` list the mapping below gives.
- [ ] **Step 3: Run them and see them fail** with `KeyError: '<agent>'`.
- [ ] **Step 4: Implement the adapter** and register it in `ADAPTERS`.
- [ ] **Step 5: Add an end-to-end test** in `tests/test_cli.py`. Run `--hook --agent <agent>` on the write fixture,
  with its content replaced by `// one\n// two\n` and its path pointed into the sandbox. Expect exit 2 and the C1
  line on stderr. A clean variant exits 0 with nothing printed.
- [ ] **Step 6: Write the template** under `integrations/<agent>/`, one config file per operating system where the
  agent's config can't hold both. Each runs the guard with the agent name. Check its field names against the agent's
  hook reference on the day, and fix the template if they differ.
- [ ] **Step 7: Live blocked write (owner, stop and ask).** With the template installed, the owner asks the agent to
  write a file with a two-line comment. Expected: the write is blocked and the agent sees the report. If the agent
  never sees the report, do Step 7b.
- [ ] **Step 7b, only if Step 7 showed the report doesn't reach the model: the JSON shim.**
  1. Add the agent to `cli.JSON_VERDICT_AGENTS` (create it in the first task that needs it).
  2. For those agents, a rejected write prints the agent's JSON on stdout and exits 0, with the same text as the
     stderr report in the reason field. A crash or failure to scan is still exit 2.
  3. Test both paths in `tests/test_cli.py`.
  4. Update `CLAUDE.md` E3 to the reworded text in the spec's section 3, in the same commit.
- [ ] **Step 8: Commit** the adapter, fixtures, tests and template. Add the agent's README row (Task 8 builds the
  table).

#### Task 2: Copilot (CLI and cloud agent)

- **Fixtures:** capture with the event spelled `PreToolUse` in `.github/hooks/agent-comment-lint.json`
  (`"version": 1`). Copilot then sends Claude-shaped `tool_name` and `tool_input`.
- **Mapping:**
  - Copilot's file-creating tool becomes `Target("Write", path, {"file_path": path, "content": content})`.
  - Its string-replacing tool becomes `Target("Edit", path, {"file_path", "old_string", "new_string"})`.
  - Take the tool names from the fixtures.
  - Every other tool gives `[]`.
- **Template:** `integrations/copilot/agent-comment-lint.json`, to be copied to `.github/hooks/`. It serves both the
  CLI and the cloud agent, which reads only the default branch.
- **Block channel:** `permissionDecision: "deny"` with `permissionDecisionReason` is documented, and exit 2 also
  denies. Step 7 decides whether stderr reaches the model.
- **Fail-closed:** errors block; timeouts let the write through. That holds on every operating system.

#### Task 3: Windsurf / Devin

- **Fixtures:** the `pre_write_code` event.
- **Mapping:** `tool_info.file_path` plus `edits[{old_string, new_string}]` becomes
  `Target("MultiEdit", path, {"file_path": path, "edits": edits})`. An edit with an empty `old_string` on a missing
  file creates it, as `hook._replaced` already handles. Any other event gives `[]`.
- **Template:** `integrations/windsurf/hooks.json`, to be copied to `.devin/hooks.json`, with a note about the legacy
  `.windsurf/` path.
- **Block channel:** exit 2 with stderr.
- **Fail-closed:** no. A crash or timeout lets the write through on every operating system. The guard still turns a
  missing command into a block.

#### Task 4: Kiro

- **Fixtures:** `PreToolUse` with matcher `fs_write`. Capture each of `create`, `str_replace`, `insert` and `append`.
- **Mapping** (the `command` field picks the shape):
  - `create` becomes `Write(path, file_text)`.
  - `str_replace` becomes `Edit(path, old_str, new_str)`.
  - `insert` becomes a new pseudo-tool `Target("Insert", path, {"file_path", "insert_line", "new_str"})`.
  - `append` becomes `Target("Append", path, {"file_path", "new_str"})`.
- **`proposed_text` gains two branches:**
  - `Insert` puts `new_str` after line `insert_line` (0 means the top). It returns None when the file is missing or
    the line is out of range.
  - `Append` adds `new_str` to the end. A missing file counts as empty.
  - Test both in `tests/test_hook.py`.
- **Template:** `integrations/kiro/agent-comment-lint.json`, to be copied to `.kiro/hooks/`.
- **Block channel:** exit 2 with stderr.
- **Fail-closed:** undocumented, so README says "not promised".

#### Task 5: Cursor

- **Fixtures:** `preToolUse` with matcher `Write`. Capture both a new file and an edit, because the edit shape is
  unverified. If an edit arrives as a full new `content`, map it to `Write`. If it arrives as old/new pairs, map it to
  `MultiEdit`.
- **Mapping:** `file_path` plus `content` becomes `Write`. Other shapes follow the fixture, as above.
- **Template:** `integrations/cursor/hooks.json`, to be copied to `.cursor/hooks.json` (`"version": 1`), with
  `failClosed: true`.
- **Block channel:** `permission: "deny"` with `agent_message` is documented, and exit 2 also denies. Step 7 decides
  whether stderr reaches the model.
- **Fail-closed:** yes, with `failClosed: true`, on every operating system.

#### Task 6: Codex CLI

- **Fixtures:** `PreToolUse` for `apply_patch`, with the patch in `tool_input.command`. Capture:
  - one patch that adds a file;
  - one that updates a file with an `@@` anchor;
  - one that deletes a file;
  - one wrapped in a heredoc.
- **Parser** (`hook.parse_codex_patch(text) -> list[CodexFile]`):
  - `CodexFile = namedtuple("CodexFile", ["kind", "path", "move_to", "content", "hunks"])`, where `kind` is `"add"`,
    `"update"` or `"delete"`.
  - `CodexHunk = namedtuple("CodexHunk", ["anchor", "old_lines", "new_lines", "at_end"])`.
  - Accept the patch with or without a surrounding heredoc. Read between `*** Begin Patch` and `*** End Patch`.
  - The grammar follows `codex-rs/apply-patch/src/parser.rs`.
  - Raise `HookInputError` on text that isn't a patch.
- **Application** (`hook.apply_codex_hunks(text, hunks) -> str | None`):
  - For each hunk, move a cursor to the anchor line when there is one, then find `old_lines` at or after the cursor.
  - Lines are compared exactly first, then with trailing whitespace stripped, then with both ends stripped, as Codex
    does.
  - `at_end` hunks must match at the end of the file.
  - The result is None when any hunk doesn't match.
- **Mapping:**
  - `add` becomes `Write(path, content)`.
  - `update` becomes `Target("CodexPatch", move_to or path, {"file_path": path, "hunks": hunks}, must_apply=True)`.
    `proposed_text` applies it to the current text of `file_path`.
  - `delete` gives nothing.
- **Tests, in addition to the shared steps:**
  - parser tests for add, update, delete, move and heredoc;
  - application tests for anchors, each whitespace level, end-of-file and a mismatch giving None;
  - CLI tests:
    - a two-file patch whose second file adds a two-line comment blocks, naming that file (Review Focus 2);
    - a delete-only patch exits 0 (Review Focus 3);
    - a patch whose context matches nothing exits 2 with `PATCH_NOT_APPLIED`.
- **Template:** `integrations/codex/hooks.json`, to be copied to `.codex/hooks.json`, with a note that hooks must be
  trusted through `/hooks`.
- **Block channel:** exit 2 with stderr.
- **Fail-closed:** undocumented, so "not promised".

#### Task 7: Gemini CLI, or Antigravity

- **Step 0 (before Step 1):** check whether the consumer CLI is now Antigravity, and capture the event names there.
  Use whichever product the owner runs, and name the adapter `gemini` either way.
- **Fixtures:** the `BeforeTool` event for `write_file` and for `replace`.
- **Mapping:**
  - `write_file` becomes `Write(file_path, content)`.
  - `replace` becomes `Edit(file_path, old_string, new_string)` with `replace_all = allow_multiple`.
  - The `instruction` field is ignored.
- **Template:** `integrations/gemini/settings.json`, as a fragment for `.gemini/settings.json`, or for the
  Antigravity equivalent.
- **Block channel:** `{"decision": "deny", "reason"}` or exit 2.
- **Fail-closed:** no. Other exits continue with a warning, and the timeout is 60 s.
