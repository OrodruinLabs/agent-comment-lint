# Release 1.3.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the routes around the write-time hook and remove the clean-up needed before adopting pre-commit. This
release adds:
- an end-of-session check that judges only what changed since the session started;
- a `--staged` mode with a second pre-commit hook id;
- one or two lines of guidance at session start;
- committed settings for the hook and the end-of-session check.

**Architecture:**
- `gitio` gains a raw-bytes runner, tree-to-tree and index spans, a snapshot that builds a tree from a temporary copy
  of the index, and blob reads.
- A new `session` module owns where snapshots are stored.
- `cli` shares one changed-lines runner between `--diff`, `--staged` and the Stop check. `--hook` dispatches on the
  event's `hook_event_name`, so the plugin keeps a single wrapper.

**Tech Stack:** Python 3.9+ standard library and `unittest`; git; POSIX `sh` (Git Bash on Windows).

**Spec:** `docs/superpowers/specs/2026-10-29-next-level-roadmap-design.md`, section 5 (items 5.1 to 5.4).

**Depends on:** release 1.2.0 being merged. This plan uses `report.hook_text(result, texts, header, closing)`,
`report.HOOK_CLOSING`, `report.WRITE_RETRY`, `cli.HOOK_HEADER`, `cli._hook_closing(tool)` and the interpreter-finding
wrapper.

## Global Constraints

- Python 3.9 or newer, standard library only at run time. `check-agent-comment-lint.py` keeps working from a plain
  checkout (E1).
- Exit codes: 0 clean, 1 violations, 2 could not scan. Exit 2 is never downgraded (E2).
- In `--hook` mode and in the wrapper, any rejected write or crash is exit 2 (E3).
- No configurable limits, no inline suppression. Settings only exclude paths or add governance (E4).
- `python3 check-agent-comment-lint.py --all` stays clean (E5). Code lines are at most 120 characters (E6).
- Every behaviour change has a test written first and seen failing (E7).
- One version, `1.3.0`, in `agent_comment_lint/__init__.py` and `.claude-plugin/plugin.json` (E8).
- Everything works on macOS, Linux and native Windows. CI from 1.2.0 runs all three.
- The snapshot never writes the real index, the working tree or any ref. It writes only git objects and files under
  `git rev-parse --git-path agent-comment-lint/sessions`.
- A session start never fails visibly because of the snapshot. Any snapshot failure means "no snapshot".
- Run one test file with `python3 -m unittest discover -s tests -p 'test_cli.py' -k NAME`.

## Review Focus

1. **A file the session deletes** should not crash the Stop check and should not be judged. Test in Task 3.
2. **A file renamed during the session with its content unchanged** should not be read. Test in Task 3.
3. **A violation fixed in a later turn.** Stop runs at the end of every turn, so once Claude fixes the violation, the
   next Stop should pass. Test in Task 3.
4. **A staged file that is not UTF-8 text** should be exit 2, not a pass. Test in Task 2.
5. **An ignored file written during the session**, such as a covered file under a `.gitignore` entry, should not be
   judged, as `--all` doesn't judge it. Test in Task 3.

**Interfaces:**
- Produces:
  - `gitio._git_bytes(root, *args, env=None) -> bytes`. It holds today's runner logic; `env` is a dict merged over
    the pinned environment. `gitio._git` keeps its signature and decodes `_git_bytes`.
  - `gitio.diff_span(root, base) -> tuple`, which now returns `(base + "...HEAD",)`.
  - `gitio.STAGED_SPAN = ("--cached",)`.
  - `gitio.changed_files(root, span: tuple)` and `gitio.changed_diff(root, span: tuple)`, which pass `*span` after
    `DIFF_SHAPE`.
  - `gitio.snapshot_tree(root, paths) -> str`, the id of a tree, built as follows:
    1. Copy the real index (`git rev-parse --git-path index`, if it exists) to a temporary file outside the working
       tree.
    2. With `GIT_INDEX_FILE` set to that file, feed `paths` NUL-separated to
       `git update-index --add --remove -z --stdin`.
    3. Run `git write-tree`.
    4. Delete the temporary file in every case.
  - `gitio.blob(root, spec) -> bytes` runs `git cat-file blob <spec>`, with GitError on failure.
  - `gitio.has_head(root) -> bool` runs `git rev-parse --verify -q HEAD`. It returns False on exit 1 and raises
    GitError on any other failure.
  - `gitio.committed_blob(root, path) -> bytes | None`: None when `git ls-tree -z HEAD -- <path>` prints nothing,
    otherwise `blob(root, "HEAD:" + path)`.
  - `gitio.git_path(root, name) -> str` is the absolute form of `git rev-parse --git-path <name>`.

**Interfaces:**
- Consumes: `gitio.snapshot_tree`, `gitio.git_path`, `gitio.listed_files` and `gitio.changed_*` with a span tuple from
  Task 1; `cli._run_changes` and `cli._blob_reader` from Task 2; `report.hook_text` from 1.2.0.
- Produces, in `session.py`:
  - `SESSIONS = "agent-comment-lint/sessions"`;
  - `SESSION_ID = re.compile(r"^[A-Za-z0-9_-]{1,128}$")`;
  - `MAX_AGE_SECONDS = 7 * 24 * 3600`;
  - `record(directory: str, session_id: str, tree: str) -> None`. It writes `<directory>/<session_id>` holding `tree`
    only if that file doesn't exist yet, and removes files in `directory` older than `MAX_AGE_SECONDS`.
  - `recorded(directory: str, session_id: str) -> str | None`.

  Both take the directory, so they need no git. The caller passes `gitio.git_path(root, SESSIONS)`.
- Produces, in `cli.py`:
  - `_covered_paths(root, config) -> list`, the paths of `gitio.listed_files(root)` that `_judged` accepts;
  - `HOOK_STOP_HEADER = "Before you finish: agent-comment-lint found comments this session added that break the policy.\n" "Only lines changed since this session started are judged.\n"`;
  - `STOP_CLOSING = ("Fix these comments before you finish; the check runs again when you stop.", report.HOOK_CLOSING[1], report.HOOK_CLOSING[2])`.
- Dispatch:
  - `hook_event_name` missing or `"PreToolUse"` takes today's path.
  - `"SessionStart"` calls `_record_session` and always gives a clean report.
  - `"Stop"` calls `_run_session_end`.
  - Any other event name is let through as clean.

  Only the Stop verdict uses `HOOK_STOP_HEADER` and `STOP_CLOSING`.
- `_run_session_end(run, root, load_config, event)`:
  - **Lets the session end** when the root is not a git work tree, the session id fails `SESSION_ID`, or no snapshot
    is recorded.
  - **Otherwise judges the span** `(snapshot, snapshot_tree(root, _covered_paths(root, config)))` through
    `_run_changes`, with `_blob_reader(now + ":")` as the reader.
  - **Fails the scan** on a GitError, which surfaces as exit 2.
- `hooks/hooks.json` gains:
  - `"SessionStart": [{"hooks": [{"type": "command", "command": <same wrapper command>, "timeout": 30}]}]`;
  - `"Stop": [{"hooks": [{"type": "command", "command": <same wrapper command>, "timeout": 60}]}]`.

  Neither gets an `onFailure`.

### Task 4: The hook and the end-of-session check read committed settings (design item 5.4)

**Files:**

**Interfaces:**

- Produces: `cli._load_hook_config(args, root, cwd) -> Config`. It decides as follows:

    decoded with `ENCODING` strictly; a decode error is `ConfigError("is not UTF-8 text")`.
