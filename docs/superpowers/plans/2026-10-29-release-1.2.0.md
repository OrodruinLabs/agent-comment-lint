# Release 1.2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make agent-comment-lint work on every operating system, make the hook block only what it should, teach the
agent the fix, catch plan and chat references, and make the tool easy to install and easy to see in a pull request.

**Architecture:** All changes stay inside the existing modules. A new hook renderer lives in `report.py`, the new pack
lives in `governance.py`, and the changed-line fix lives in `hook.py`. CI, the Action, the release workflow and the
plugin wrapper are extended in place. No new runtime module.

**Tech Stack:** Python 3.9+ standard library and `unittest`; POSIX `sh` (Git Bash on Windows); GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-29-next-level-roadmap-design.md`, sections 3 and 4 (items 4.1 to 4.8).

## Global Constraints

- Python 3.9 or newer, standard library only at run time. `check-agent-comment-lint.py` keeps working from a plain
  checkout (E1).
- Exit codes: 0 clean, 1 violations, 2 could not scan. Exit 2 is never downgraded (E2).
- In `--hook` mode and in `hooks/agent-comment-lint-hook.sh`, any non-zero verdict and any crash is exit 2 (E3).
- No configurable limits and no inline suppression. Settings only exclude paths or add governance (E4).
- `python3 check-agent-comment-lint.py --all` stays clean: every comment in this repository is at most one prose line,
  holds no governance reference, and sits on a line of at most 120 characters (E5).
- Code lines in `agent_comment_lint/` and `tests/` are at most 120 characters (E6).
- Every behaviour change has a test written first and seen failing (E7).
- One version, in `agent_comment_lint/__init__.py` and `.claude-plugin/plugin.json` (E8). This release is `1.2.0`.
- The finding line `path:line: RULE: message` stays byte for byte. `tests/test_packaging.py:60` pins it.
- Everything works on macOS, Linux and native Windows.
- Run one test file with `python3 -m unittest discover -s tests -p 'test_hook.py' -k NAME`. Do not use
  `python3 -m unittest tests.test_hook`, which fails with "No module named 'support'".

## Review Focus

1. **Far-apart edits.** An Edit with `replace_all` that changes two lines far apart in a long repetitive file should
   report exactly those two lines, nothing between them. Test in Task 2.
2. **Long blocks.** A comment block longer than the excerpt cap should show 6 lines and then say how many more there
   are, not dump the whole block. Test in Task 3.
3. **Long lines.** A C7 finding on a line over 120 characters should show the line cut at 120 characters and marked as
   cut. Test in Task 3.
4. **A bad `$schema`.** A `$schema` whose value is not a string should still be exit 2, like any malformed settings
   file. Test in Task 6.
5. **Windows paths.** A Windows `file_path` that differs from the root only in letter case or in its separator should
   be judged, not let through as "outside the root". Test in Task 1.

### Task 3: A block message that teaches the fix (design item 4.2)

**Files:**
- Modify: `agent_comment_lint/report.py` (new function and constants)
- Modify: `agent_comment_lint/cli.py` (`HOOK_BLOCKED`, `_Run`, `_run_hook`, `_hook_verdict`, the crash path in `main`)
- Test: `tests/test_report.py`, `tests/test_cli.py` (`TestHookMode`)

**Interfaces:**
- Produces: `report.hook_text(result: Report, texts: dict, header: str, closing: tuple) -> str`. It returns the
  whole stderr text of a blocked hook:
  - `header`, as given;
  - per finding, the finding line, its excerpt and its fix line;
  - the summary or error lines, exactly as `as_text` prints them;
  - one line per item of `closing`, only when there are findings.

  `texts` maps a root-relative path to the text that was judged. The 1.3.0 Stop check calls this with its own header
  and closing lines.
- Produces: the constants in `report.py`, with exact copy:

```python
HOOK_SCOPE = "Only the lines this write adds or changes are judged; comments elsewhere in the file are fine.\n"
FIXES = {
    "C1": "Keep one line that says why the code is this way; put the rest in the commit message or the PR description.",
    "C3": "Remove the reference; say what the code needs, not where the decision was recorded.",
    "C5": "Shorten the assertion message to at most two lines.",
    "C7": "Shorten the comment, or move it onto its own line above the code.",
}
EXCERPT_LINES = 6
EXCERPT_WIDTH = 120
HOOK_CLOSING = (
    "Fix the comment and retry the same tool call.",
    "Splitting the comment across blank lines, or writing the file another way (Bash, a script, another tool), "
    "does not satisfy the policy.",
    "Adding an exclusion to .agent-comment-lint.json is not the fix: exclusions are for generated and third-party code.",
)
WRITE_RETRY = "Re-send this Write with only the comment lines changed."
```

  Wrap the long strings with implicit concatenation so code lines stay at 120 characters or fewer (E6).
- Formatting:
  - Each excerpt line is four spaces plus the source line, without its line ending. A line longer than
    `EXCERPT_WIDTH` is cut to 119 characters plus `…`.
  - After `EXCERPT_LINES` lines comes `    … N more line(s)`.
  - Each fix line is two spaces, `Fix: `, then the rule's text.
- Produces, in `cli.py`:
  - `HOOK_BLOCKED` keeps its value;
  - `HOOK_HEADER = HOOK_BLOCKED + report.HOOK_SCOPE`;
  - `_hook_closing(tool) -> tuple`, which is `report.HOOK_CLOSING`, plus `report.WRITE_RETRY` when
    `tool == "Write"`.

  `_hook_verdict` and the crash path in `main` both start with `HOOK_HEADER`.
